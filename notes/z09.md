# З09. Сводная таблица `daily_store_revenue`

## 1. Будущий график

**Виджет на дашборде (З10):** линейный график «Оборот по дням и магазинам».
Ось X — день (`full_date`), ось Y — сумма оборота, отдельная линия на каждый магазин.

## 2. Одна строка сводки

**Одна строка `daily_store_revenue` = один день × один магазин.**

Поле `amount_sum` — сумма оборота (`sum(fs.amount)`) за этот день
в этом магазине.

⚠️ **Не путать с grain факта:**
- `fact_sales`: одна строка = **позиция в чеке** (товар × количество × сумма)
- `daily_store_revenue`: одна строка = **день × магазин**, уже агрегат

Это **разные вещи**. Факт — детальный, сводка — агрегированная.

## 3. Как построена

Materialized View `mv_daily_store`:
- Целевая таблица `daily_store_revenue` с движком `SummingMergeTree`
  (ORDER BY `full_date, store_id`) — при merge одинаковые ключи суммируются.
- При каждом INSERT в `fact_sales` MV агрегирует новые строки
  по `(full_date, store_id)` и добавляет в целевую таблицу.
- Начальное заполнение — `INSERT INTO daily_store_revenue SELECT ... FROM fact_sales`.

DDL — в `sql/mv_daily_store.sql`.

## 4. Метрика

В сводке — **та же** метрика, что в `canonical_metric.sql`: `sum(amount)`.
Никаких дополнительных фильтров, никаких изменений правил.

Это важно: если в сводке будет другая метрика — на З11 (сверка с BI)
числа разъедутся.

## 5. Сверка с детальной таблицей

Сумма `amount_sum` по всем строкам сводки должна совпадать
с `sum(amount)` из `fact_sales`.

```sql
-- Детально
SELECT sum(amount) FROM fact_sales;

-- Сводка
SELECT sum(amount_sum) FROM daily_store_revenue;
